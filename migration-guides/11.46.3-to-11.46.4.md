# Migration Guide: 11.46.3 → 11.46.4

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | None |
| **New Features** | `openDownloadStream(res, open)` is exported — the function the framework's download routes open a file stream with |
| **Bugfixes** | The documented pattern for an own download route logged an ERROR with a stack trace for every client that left before S3 answered, and answered a busy store with 500 instead of 503 (§1) |
| **Migration Effort** | Projects with their OWN download route: open the stream with `openDownloadStream()` (§1). Everyone else: `pnpm run update` |

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@11.46.4
pnpm run update   # nest-server-starter based projects
grep -rn "downloadAbortSignal(" src/   # own download routes: open the stream with openDownloadStream() (§1)
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual.

## 1. Own download routes

11.46.3 documented passing `downloadAbortSignal(res)` to `getFileStream()`, so an S3 request whose client has gone is
dropped while it waits for a socket. The aborted request then REJECTS with `AbortError`. Nothing in the documented
pattern caught it: every client that left before S3 answered became `ERROR [ExceptionsHandler] … AbortError` with a
stack trace and a `500` sent into a closed response — under exactly the load the `S3 socket pool exhausted:` line has
to stand out in. A store that handed out no connection in time (`TimeoutError`) reached Nest as a `500` instead of the
`503` with `Retry-After` the framework's routes answer.

The framework's routes were not affected: they open the stream through `openDownloadStream()`, which was a protected
controller method until now. It is exported since 11.46.4:

```typescript
import { downloadAbortSignal, openDownloadStream, pipeFileToResponse, RESPONSE_GONE } from '@lenne.tech/nest-server';

@Get('image/:id')
async image(@Param('id') id: string, @Res() res: Response, @CurrentUser() currentUser) {
  const stream = await openDownloadStream(res, () =>
    this.fileService.getFileStream(id, { abortSignal: downloadAbortSignal(res), currentUser }),
  );
  if (stream === RESPONSE_GONE) {
    return res; // nobody left to deliver to
  }
  if (!stream) {
    throw new NotFoundException();
  }
  res.header('Content-Type', 'image/png');
  return pipeFileToResponse(stream, res);
}
```

`openDownloadStream()`:

- does not ask the store when the client has already gone,
- answers `RESPONSE_GONE` when the store request failed because the client left meanwhile,
- destroys a stream that arrives after the client left,
- answers `503` with `Retry-After: 5` for `TimeoutError`, and rethrows every other error,
- passes `null` (the service's rights check refused) on unchanged.

`open` may return any stream: `CoreS3Service.getObject()` callers pass `async () => (await s3.getObject(key, { abortSignal })).body`.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ERROR [ExceptionsHandler] … AbortError` with a stack trace, often in bursts under load | an own download route passes `downloadAbortSignal(res)` but opens the stream without `openDownloadStream()` | §1 |
| Own download route answers `500` while `S3 socket pool exhausted` is logged | the `TimeoutError` of a busy store is not turned into a `503` | §1 |
