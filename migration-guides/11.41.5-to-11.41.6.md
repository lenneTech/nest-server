# Migration Guide: 11.41.5 → 11.41.6

## Overview

| Category              | Details                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------- |
| **Breaking Changes**  | None                                                                                      |
| **Dependencies**      | `@types/nodemailer` dropped (nodemailer 10 ships its own declarations)                    |
| **Security**          | Two critical advisories in the SWC dev tooling (`piscina`, `@xhmikosr/decompress`) (§2)   |
| **Migration Effort**  | No code changes; a lockfile refresh, and one override key to widen in starter-based projects |

## Quick Migration

```bash
pnpm update @lenne.tech/nest-server
pnpm update piscina --depth Infinity   # only if `pnpm audit` reports GHSA-67c8-pqhq-4rmx (§2)
# starter-based projects: widen the @xhmikosr/decompress override key (§2)
pnpm run build && pnpm test
```

Vendor-mode projects have nothing to pick up from `src/core/` in this release.

## What's New in 11.41.6

### 1. `@types/nodemailer` is gone

nodemailer 10 (since 11.41.5) is a TypeScript rewrite that ships its own declarations, so the
separate `@types/nodemailer` package is no longer read. This repository dropped it from its
devDependencies. If your project lists it, you can remove it as well:

```bash
pnpm remove @types/nodemailer
```

Keeping it does no harm — TypeScript resolves the declarations bundled with `nodemailer` first —
but it is a package to keep updated that nothing uses.

### 2. Two critical advisories in the SWC dev tooling — fix them in YOUR project

Both reach a project through `@swc/cli` (which `@nestjs/cli` uses for SWC builds), and neither
can be fixed from here: this repository's lockfile and overrides do not reach your project.

#### `piscina`

`piscina` < 4.9.4 is covered by **GHSA-67c8-pqhq-4rmx** (critical, prototype-pollution gadget in
`ThreadPool.options`). `@swc/cli` depends on `piscina@^4.3.1`, and the fixed 4.9.4 is inside
that range, so no override is needed — only a lockfile refresh:

```bash
pnpm update piscina --depth Infinity
pnpm audit
```

nest-server-starter 11.41.6 already resolves 4.9.4.

#### `@xhmikosr/decompress`

**GHSA-hrh2-vp3x-79xf** (critical, path traversal via a symlink chain) covers
`@xhmikosr/decompress >= 11.0.0, <= 11.1.3`; 11.1.4 is fixed. Projects created from
nest-server-starter carry this override in `pnpm-workspace.yaml`:

```yaml
'@xhmikosr/decompress@>=11.0.0 <11.1.3': 11.1.4
```

Its key stops one patch short: 11.1.3 is vulnerable too, and a project that resolves it is not
caught. Widen the key and refresh:

```yaml
'@xhmikosr/decompress@>=11.0.0 <11.1.4': 11.1.4
```

```bash
pnpm install
pnpm audit
```

nest-server-starter 11.41.6 ships the widened key.

### 3. Under the hood

`EmailService` is now covered by a test that sends through a real SMTP handshake (STARTTLS,
authentication, attachment, `requireTLS` refusing a server without STARTTLS) instead of only
`jsonTransport`. No behaviour changed.

## Compatibility Notes

| Pattern | Status |
| ------- | ------ |
| `@types/nodemailer` in your devDependencies | Unused; safe to remove |
| Code typing `nodemailer/lib/…` transports as `X.default` (11.41.5) | Unchanged |
| A lockfile resolving `piscina@4.9.3` | Vulnerable — refresh it (§2) |
| Override `'@xhmikosr/decompress@>=11.0.0 <11.1.3': 11.1.4` | Misses 11.1.3 — widen the key to `<11.1.4` (§2) |

## Troubleshooting

| Symptom | Cause | Fix |
| ------- | ----- | --- |
| `pnpm audit` reports GHSA-67c8-pqhq-4rmx (`piscina`) | Lockfile still resolves 4.9.3 | `pnpm update piscina --depth Infinity` |
| `pnpm update piscina` changes nothing | An override pins `piscina` | Raise or remove the override to `4.9.4` |
| `pnpm audit` reports GHSA-hrh2-vp3x-79xf (`@xhmikosr/decompress`) | Override key `<11.1.3` misses 11.1.3 | Widen the key to `<11.1.4` |
