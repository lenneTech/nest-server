# Migration Guide: 12.8.4 → 12.8.5

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | None |
| **New Features** | None |
| **Bugfixes** | Security: error responses of `HttpExceptionLogFilter` no longer contain `options` / `cause` (§1) |
| **Migration Effort** | None |

12.8.5 is a security patch for 12.8.4. The same fix ships in 12.6.8 (`latest-12.6`) and 11.46.1 (`latest-11`).

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@12.8.5
pnpm run update   # nest-server-starter based projects
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual.

## 1. Error responses no longer contain `options` / `cause`

`HttpExceptionLogFilter` (registered by nest-server-starter's `main.ts` while `logExceptions` is on, its default)
answered a REST request with every field of the exception — including `options` and the `cause` the throwing code
passed (`new BadRequestException('…', { cause: dbError })`). An internal error message, a query or a connection
string could reach the client that way.

**What changed:** error responses now leave `options` and `cause` out. `response`, `status`, `message` and `name` stay
as before, so frontends that read them need no change. The cause is still logged. A test that asserted `options` or
`cause` in an error body has to drop that assertion.
