# Migration Guide: 11.43.3 → 11.43.4

A security patch for projects that still run on 11.x. It is published under the npm dist-tag `latest-11`, not `latest`:
12.x stays the version a plain install resolves to, and moving every project to 12.x remains the goal. This release
carries only urgent security fixes; functional fixes from 12.x are not backported.

## Overview

| Category             | Details                                                                                                                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Bugfixes**         | A legacy logout ends the device's refresh token; with `allDevices` it ends every device (§1). The legacy REST rate limit can no longer be bypassed with a query string (§1b)                                                   |
| **New Features**     | None                                                                                                                                                                                                                          |
| **Framework API**    | Unchanged                                                                                                                                                                                                                     |
| **Dependencies**     | `nodemailer` 10.1.2 → 10.1.4 (§2), `multer` 2.4.0 → 2.5.0 (§3)                                                                                                                                                                |
| **Breaking Changes** | None                                                                                                                                                                                                                          |
| **Migration Effort** | Raise the version, add or raise the `multer` override (§3), refresh four transitive packages (§4)                                                                                                                             |

## Quick Migration

```bash
# npm mode: the version is pinned exactly, and `latest` is 12.x, so name the version
pnpm add @lenne.tech/nest-server@11.43.4
```

Then add the `multer` override from §3 to `pnpm-workspace.yaml` (or raise the one you already have), raise the
`body-parser` and `fast-uri` entries from §4 if your project carries them, and refresh:

```bash
pnpm install
pnpm update --depth Infinity body-parser zod fast-uri @hono/node-server
pnpm audit --prod
pnpm test
```

Vendor-mode projects update the core to the tag `11.43.4` with the core updater and apply §3 and §4 the same way.

## 1. A legacy logout did not end the refresh token

`CoreAuthService.logout()` removed the device from `refreshTokens` and wrote the map back through `update()`. `update()`
merges its input into the stored record, so a key that is merely missing from the input survives: the logged-out
device's refresh token kept working, and `logout(allDevices)`, which wrote an empty map, left every device signed in.
A user who signed out, or signed out everywhere after losing a device, stayed reachable for whoever held the refresh
token.

The logout now writes `null` for every device it ends, in `refreshTokens` and `tempTokens`; `validateUser()` reads a
`null` device as signed out. No action is needed. A project that overrides `logout()` and writes the token maps itself
must do the same: write `null` for an ended device, never delete its key.

This affects every project that keeps the legacy endpoints open (`auth.legacyEndpoints`, or the three-argument
`CoreModule.forRoot()` from before 11.38.0). IAM (Better-Auth) sessions are not affected.

## 1b. The legacy REST rate limit counted every spelling of a route separately

`LegacyAuthRateLimitGuard` keyed the REST counter on the last segment of `request.url`, query string included. Express
routes `/auth/signin?n=1`, `/auth/signin?n=2` and `/auth/SignIn/` to the same handler, but each got a fresh bucket, so
`auth.rateLimit` never stopped password guessing against `/auth/signin` (or sign-up spam against `/auth/signup`). The
counter is now keyed on the route handler. No action is needed; projects with `auth.rateLimit` configured and the legacy
REST endpoints open are the ones that were exposed.

## 2. nodemailer 10.1.4

Three advisories in nodemailer's address parser, all moderate (CVSS 6.5), all patched in 10.1.4: a nested comment
([GHSA-8c8m-p3m8-cjg8](https://github.com/advisories/GHSA-8c8m-p3m8-cjg8)), a `;` inside a quoted string
([GHSA-m943-m63m-w62w](https://github.com/advisories/GHSA-m943-m63m-w62w)) and a `>` inside a quoted local part
([GHSA-85x2-q946-cp5h](https://github.com/advisories/GHSA-85x2-q946-cp5h)) each turn text of an address into an
additional recipient. nest-server pins nodemailer itself, so raising the framework is enough. A project that declares
its own `nodemailer`, or carries an override for it, raises that to 10.1.4 as well.

## 3. multer 2.5.0 — the override is needed again

[GHSA-q7qp-rjg7-q26m](https://github.com/advisories/GHSA-q7qp-rjg7-q26m) (high, CVSS 7.5): a pending asynchronous
`fileFilter` after the request was torn down leads to a denial of service. It covers 2.4.0, patched in 2.5.0.

nest-server now declares 2.5.0, but every `@nestjs/platform-express` 11.x up to 11.2.8, the newest, pins multer
**exactly** (2.4.0), and `FileInterceptor` uses that copy. No 11.x update reaches the fix, so the project needs an
override:

```yaml
# pnpm-workspace.yaml of the project
overrides:
  # @nestjs/platform-express 11.x exact-pins multer 2.4.0 (GHSA-q7qp-rjg7-q26m, fixed 2.5.0)
  'multer@>=2.0.0 <2.5.0': '2.5.0'
```

A project that already mirrors the older entry (`'multer@>=2.0.0 <2.4.0': '2.4.0'`) must raise both key and target:
the old target is the vulnerable version.

## 4. Transitive packages: refresh the lockfile

Four advisories of the same week sit in packages nest-server does not pin; they are fixed by a lockfile refresh in the
project (the command in Quick Migration):

| Package | Advisory | Patched |
| ------- | -------- | ------- |
| `body-parser` (via `@apollo/server`, express) | [GHSA-27r3-jxmh-p828](https://github.com/advisories/GHSA-27r3-jxmh-p828), high | 2.4.0 |
| `zod` (via `@modelcontextprotocol/sdk`) | [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), high | 4.6.6 |
| `fast-uri` (via ajv) | four advisories up to moderate | 3.1.9 |
| `@hono/node-server` (via `@modelcontextprotocol/sdk`) | [GHSA-rmxm-3fg6-px4f](https://github.com/advisories/GHSA-rmxm-3fg6-px4f), moderate | 2.1.3 |

**A project that carries an override for `body-parser` or `fast-uri`** (starter-based projects do) must raise it, or
the old target keeps the vulnerable version in place:

```yaml
  'body-parser@>=2.0.0 <2.4.0': '2.4.0'   # was '<2.3.0': '2.3.0'
  'fast-uri@<3.1.9': '3.1.9'              # was '<3.1.8': '3.1.8'
```

`pnpm run check:overrides`, where a project has it, reports each of these as `TOO LOW`.

## Not in this release

Fixes from 12.x that are not urgent security fixes stay there, among them the configuration dump of a second
`new ConfigService()` (12.0.0) and the fixes for `distinct()` over ObjectId fields and for names lost at an IAM sign-in
(12.1.0). They arrive with the move to 12: `migration-guides/11.43.x-to-12.0.x.md`.
