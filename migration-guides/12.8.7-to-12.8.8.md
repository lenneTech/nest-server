# Migration Guide: 12.8.7 → 12.8.8

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | None |
| **New Features** | None |
| **Bugfixes** | Security: undici 7.30.2 and nodemailer 10.4.1 close eight advisories in the framework's runtime dependencies (§1) |
| **Migration Effort** | `pnpm run update`. A project that pins undici or nodemailer itself — vendored cores included — raises them (§1) |

12.8.8 is a security patch for 12.8.7 (`latest`): dependencies only, the framework's code is unchanged.
The same update ships in 12.6.9 (`latest-12.6`) and 11.46.2 (`latest-11`).

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@12.8.8
pnpm run update   # nest-server-starter based projects
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual, and raise undici and nodemailer in the project's
own `package.json` (§1).

## 1. undici 7.30.2 and nodemailer 10.4.1 (security)

| Package | From | To | Advisories |
|---|---|---|---|
| `undici` | 7.30.1 | 7.30.2 | GHSA-mqg3-3v4r-cm32 (high: cache poisoning and cross-user disclosure via interceptors), GHSA-7xg3-fphp-28hg, GHSA-3g9m-rv3r-w5w2, GHSA-5rm8-gv32-r954, GHSA-9v6h-8rgp-m69f, GHSA-r4pc-4jcp-7pqc (medium) |
| `nodemailer` | 10.4.0 | 10.4.1 | GHSA-3q53-mvfw-q9v8, GHSA-2g53-87p2-4qq8 (medium: address parsing and the IDN allow-list) |

The framework uses undici for `outboundFetch()` (the SSRF-guarded fetch for user-entered URLs) and nodemailer for
`EmailService`. Both versions are patch or minor releases of the line the framework already used; nothing in their API
that the framework calls changed.

**A project that pins either package itself** (a direct `nodemailer` or `undici` dependency, an `overrides:` entry, a
vendored core whose `package.json` carries the framework's dependencies): raise it to the version above. Two copies of
undici or nodemailer otherwise stay in the tree, and the project's own one keeps the advisories.

**pnpm's release-age hold-back:** nodemailer 10.4.1 was published on 2026-11-10 08:17 UTC. A project that enforces
`minimumReleaseAge` (pnpm 11 default: one day) and installs before 2026-11-11 08:17 UTC needs
`minimumReleaseAgeExclude: [nodemailer@10.4.1]` in `pnpm-workspace.yaml`; after that time the entry is inert and can go.
