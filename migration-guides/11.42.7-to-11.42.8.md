# Migration Guide: 11.42.7 → 11.42.8

## Overview

| Category             | Details                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| **Bugfix**           | `setupSwagger()` enriches every operation an `@All()` route produces, including `SEARCH` (§1)        |
| **Bugfix**           | The Better-Auth pass-through route no longer appears as `/iam/{path}` in the Swagger document (§2)   |
| **Dependencies**     | dev: `vite` 8.3.3; override `js-yaml` 5.4.3 (§3)                                                     |
| **Breaking Changes** | None                                                                                                 |
| **Migration Effort** | None for most projects. Regenerate a client built from `/api-docs-json` if you keep one (§2)         |

## Quick Migration

```bash
pnpm update @lenne.tech/nest-server
```

Vendor-mode projects pick it up with the core update.

## 1. `SEARCH` operations of `@All()` routes are enriched

For an `@All()` route, `@nestjs/swagger` documents one operation per HTTP method — including
`SEARCH`, which no OpenAPI version lists as a path-item method. 11.42.7 walked a fixed list of
methods and skipped it, so that one operation stayed as Swagger built it: no API-token scope line,
no `security: []` on a public route, no tenant header, and `operationTags` did not reach it — it
landed in its own tag group next to the regrouped siblings.

The helper now reads the operations from the path item itself, so `SEARCH` (and any other method
`@nestjs/swagger` emits) is treated like every other operation — in the full document and in the
API-token view.

Nothing to change in your code. If you assert on the document in tests, a `search` operation of an
`@All()` route now carries the same `x-api-token-scopes`, description line and tags as its siblings.

## 2. `/iam/{path}` is gone from the document

`CoreBetterAuthController.handlePluginRoutes` (`@All('*path')`) forwards every other `/iam/*` request
to Better-Auth's own handler. It appeared in Swagger as eight `/iam/{path}` operations without
parameters or description. It is now `@ApiExcludeEndpoint()`; the route itself is unchanged.

- **Generated clients:** a client generated from `/api-docs-json` (hey-api, openapi-generator, …)
  loses its `coreBetterAuthControllerHandlePluginRoutes*` functions on the next generation. They
  could not express any real Better-Auth call, so nothing should depend on them — but regenerate and
  let the compiler confirm it.
- **Own controller:** a project controller that **overrides** `handlePluginRoutes` (re-declaring
  `@All('*path')`) must also re-declare `@ApiExcludeEndpoint()` to keep it out of the document.
  Decorator metadata belongs to the method, so an override starts without it. A controller that
  only inherits the method is covered automatically.

## 3. Dependency updates

Maintenance only, nothing to change in your project:

| Package | Old | New | Where |
| --- | --- | --- | --- |
| `vite` | 8.3.2 | 8.3.3 | devDependencies (test tooling) |
| `js-yaml` 5.x | 5.4.2 | 5.4.3 | override target in `pnpm-workspace.yaml` (parser bug fix) |

`mongoose` 9.11.0 / `mongodb` 7.7.0 are deliberately not part of this release: the framework and the
starter have to raise `mongodb` together, because two driver copies make Better-Auth's Mongo adapter
reject each other's ids.

## Compatibility Notes

- Both changes only affect the generated Swagger/OpenAPI document. Routing, guards and API-token
  enforcement are unchanged.
- The document gets smaller: the framework's own test server goes from 142 to 134 operations.
