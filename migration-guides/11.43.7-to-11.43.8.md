# Migration Guide: 11.43.7 → 11.43.8

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | None for the server API. `GET /iam/list-sessions` no longer carries a `token` field per session (§1) |
| **New Features** | `POST /iam/revoke-session` accepts `{ sessionId }` (§1) |
| **Bugfixes** | Security: `GET /iam/list-sessions` answered every session of the user with its session token (§1) |
| **Migration Effort** | None on the server. A "signed-in devices" screen that revokes a session by its `token` sends the `id` instead (§1). Pin `better-auth`, `@better-auth/core` and `@better-auth/passkey` to 1.7.16 (§2) |

11.43.8 is a security patch on the 11.x line, published under the dist-tag `latest-11` (backport of 12.6.2 / 12.7.0).

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@11.43.8
pnpm run update   # nest-server-starter based projects
pnpm run build
pnpm test
```

Vendor-mode projects update the core to the tag `11.43.8`: `/lt-dev:backend:update-nest-server-core --target 11.43.8`.
Without `--target` the updater syncs to the latest tag, which is on the 12.x line.

## 1. list-sessions names sessions by id; revoke-session takes the id

**Why:** `GET /iam/list-sessions` answered every session of the user with its `token` — the bearer credential of every
device the user is signed in on, readable by any script on the page. 11.43.7 took the session token out of the other
answers the framework forwards to Better-Auth; this was the last one.

**What changed:**

| | Until 11.43.7 | From 11.43.8 |
|---|---|---|
| `GET /iam/list-sessions` | `[{ id, token, userId, expiresAt, … }]` | `[{ id, userId, expiresAt, … }]` — no `token`, in every mode |
| `POST /iam/revoke-session` | `{ token }` | `{ sessionId }` (new) or `{ token }` (unchanged) |

`{ sessionId }` is resolved among the sessions of the signed-in user. An unknown id, or the id of another user's
session, revokes nothing — the answer is the same as for a foreign token, so it discloses nothing. Revoking by `token`
stays for clients that hold one.

**Your frontend:** a "signed-in devices" screen that revokes a session by the `token` from `list-sessions` sends the
`id` instead:

```typescript
await fetch(`${api}/iam/revoke-session`, {
  body: JSON.stringify({ sessionId: session.id }),
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  method: 'POST',
});
```

Better-Auth's client (`authClient.revokeSession({ token })`) types the body as `{ token }`; send the request yourself
as above.

## 2. better-auth 1.7.16 or newer

The peer range of `better-auth`, `@better-auth/core` and `@better-auth/passkey` is now `>=1.7.16 <1.8.0` (was
`>=1.7.7 <1.8.0`), the same as on the 12.6 line, and this release is tested against 1.7.16. `@lenne.tech/nuxt-extensions`
1.26.0 requires `>=1.7.16` too, so a fullstack project's workspace check (same range in API and app) passes again.

```bash
pnpm add better-auth@1.7.16 @better-auth/passkey@1.7.16 @better-auth/core@1.7.16
```

Keep all three on the same exact version, in the API and in the app.

## Compatibility Notes

| Pattern | Status |
|---|---|
| A client reading `token` from `list-sessions` | Gets none; use `id` and `revoke-session` with `{ sessionId }` |
| `revoke-session` with `{ token }` | Unchanged |
| `revoke-sessions`, `revoke-other-sessions`, sign-out | Unchanged |
| better-auth pinned to 1.7.7 – 1.7.15 | Below the new peer range; raise all three packages to 1.7.16 (§2) |
| A project subclass of `CoreBetterAuthService` / `CoreBetterAuthApiMiddleware` | `sessionTokenOfUser()` (public) and `resolveRevokeSessionId()` (protected) are new |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Revoking a device does nothing after the update | The screen sends the `token` from `list-sessions`, which is gone | Send `{ sessionId: session.id }` |
