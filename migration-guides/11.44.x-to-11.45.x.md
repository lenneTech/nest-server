# Migration Guide: 11.44.x → 11.45.x

## 11.45.0 changes behaviour

The version number moves only the MINOR digit (the MAJOR follows NestJS). This is the 11.x counterpart of the Swagger
default from 12.7.0 (DEV-4086):

- `setupSwagger()` serves the API documentation only in `local`, `ci` and `e2e` unless the new server option
  `swagger` is `true`. On every other stage (`develop`, `test`, `production`, …) `/swagger`, `/api-docs-json` and the
  API-token view answer 404 after the update (§1).

Nothing else changes.

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | Swagger is off outside `local` / `ci` / `e2e` unless `swagger: true` (§1) |
| **New Features** | `swagger` server option (`NSC__SWAGGER`); `isSwaggerEnabled()` exported; `setupSwagger()` takes the configuration as an optional third argument |
| **Bugfixes** | The full API description is no longer public on deployed stages (§1) |
| **Migration Effort** | Set `swagger: true` on the stages that must keep showing the API documentation (§1); check that every stage loads its own block (§2) |

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@11.45.0
pnpm run update   # nest-server-starter based projects (release/11.x)
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual. A vendored core that closed Swagger in
`main.ts` or ported the switch by hand can drop its own version: the core now carries it.

## 1. Swagger only where it is switched on

**Why:** `setupSwagger()` mounted the Swagger UI and the JSON document on every stage a project called it on,
production included. The full API description — every route, the roles it requires, every input shape — was public
there.

**What changed:** `setupSwagger()` asks `isSwaggerEnabled()` first (new server option `swagger`):

| `swagger` | `local` / `ci` / `e2e` | every other environment (`develop`, `test`, `production`, …) |
|---|---|---|
| not set | served | **off** |
| `true` | served | served |
| `false` | off | off |

Off mounts nothing: neither `/swagger` and `/swagger-api-tokens` nor `/api-docs-json` and `/api-docs-api-tokens-json`
(or the paths you gave `setupSwagger()`); they answer 404. One line in the boot log says Swagger is off. A value that
is not a boolean counts as not set, so the string `'true'` from `NEST_SERVER_CONFIG` does not switch it on;
`NSC__SWAGGER=true` arrives as a boolean.

**Your project:** nothing to do if the documentation should stay local. To keep it on a stage, set it in that
stage's block of `config.env.ts`, or through the environment:

```typescript
// config.env.ts — only the stage that should show the documentation
develop: {
  // …
  swagger: true,
},
```

```bash
NSC__SWAGGER=true
```

A client generator that reads `/api-docs-json` from a deployed stage (`openapi-typescript`, `orval`, …) needs the
switch on that stage, or reads the document from a local or CI run instead.

A test that calls `setupSwagger()` under the unit runner (`NODE_ENV=test`, which is no local environment) passes the
switch itself: `setupSwagger(app, options, { swagger: true })`.

## 2. The environment is the one the loaded block names

`isSwaggerEnabled()` reads `env` of the loaded configuration, else `NODE_ENV`. On 11.x a `NODE_ENV` that names no
block in `config.env.ts` still loads the `local` block (12.7.0 refuses that start; 11.x keeps the old behaviour), and
the `local` block counts as local — such a stage keeps serving Swagger. Check the boot line of every stage:

```
Configured for: local (requested: staging)
```

A `(requested: …)` part means the stage runs on another block than it asked for. Add a block for that `NODE_ENV`, or
set `swagger: false` in the block it falls back to.

## Compatibility Notes

| Pattern | Status |
|---|---|
| `setupSwagger(app, options)` in `main.ts` | Unchanged call; serves only where the switch allows it |
| A `main.ts` that calls `setupSwagger()` only outside production by its own check | Keeps working; the switch closes the other deployed stages too |
| `buildSwaggerDocument()` / `buildApiTokenSwaggerDocument()` used directly | Unchanged — the switch applies to `setupSwagger()` only |
| `SwaggerModule.setup()` called directly by the project | Not covered — gate it with `isSwaggerEnabled()` |
| The Hub's Swagger link on a stage with Swagger off | Answers 404 — set `swagger: true` there if the link should work |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `/swagger` or `/api-docs-json` answers 404 on a deployed stage after the update | Swagger is off outside `local` / `ci` / `e2e` | `swagger: true` in that stage's block, or `NSC__SWAGGER=true` (§1) |
| Swagger still answers on a deployed stage | The stage runs on the `local` block (boot line `Configured for: local (requested: …)`) or sets `swagger: true` | Add the missing block, or `swagger: false` (§2) |
| A unit test that serves Swagger gets 404 | The unit runner is no local environment | Pass `{ swagger: true }` as the third argument of `setupSwagger()` (§1) |
