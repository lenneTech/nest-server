# Migration Guide: 12.9.x → 12.10.x

> **This minor contains breaking changes** (see "Breaking Changes"): secret fields no longer reach the model, the client
> or an MCP client through an AI tool result; a failed OAuth sign-in without its own error URL lands on the app's login
> page instead of Better-Auth's error page; a `socialProviders.<name>.scope` that is neither a string nor a list is
> ignored. The MAJOR digit follows NestJS, so a breaking change ships as a minor here — read this guide before updating.

## Overview

| Category | Details |
|----------|---------|
| **Breaking Changes** | (1) Failed OAuth sign-ins without their own error URL, and `GET /iam/error`, now land on `<appUrl>/auth/login?error=<code>` (`betterAuth.errorUrl`, `false` restores Better-Auth's page). (2) A `socialProviders.<name>.scope` that is neither a string nor a list is ignored with an error at boot. (3) AI tool results lose every secret field (`password`, `verificationToken`, `passwordResetToken`, `passwordResetTokenExpiresAt`, `refreshTokens`, `tempTokens`, `apiKeyEncrypted`, `security.secretFields`, each also as its SQL column) — in the chat loop, in `actions[].result` and in `/ai/mcp` `tools/call` |
| **Security fixes** | GraphQL multipart uploads: one anonymous request to `/graphql` could crash the process (graphql-upload GHSA-5vm7-vc2x-p3w2, high), and duplicate file fields leaked temporary files (GHSA-qwwm-252j-9whw, medium) — fixed by the framework's own parser, no action needed (see "Security: GraphQL multipart uploads"). MCP OAuth tokens are bound to their resource (RFC 8707). With `@nestjs/ai` or `@nestjs/mcp` installed, the framework's global guards decided agent function / MCP tool calls on the tool ARGUMENTS (`switchToHttp()` is index 0 there): `{ "user": { "roles": ["admin"] } }` in a model's tool call was the authenticated caller. Now the request the call runs in decides; a request-less caller is anonymous |
| **New Features** | Social provider options reach Better-Auth (`tenantId`, `scope`, `prompt`, `mapProfileToUser`, …), `scope` from an environment variable, `betterAuth.errorUrl`; AI SDK transport (`providerType: 'nestjs-ai'`, `LlmProviderFactory.registerAiSdkModel()`), `@AgentFunction()` methods as AI tools (`ai.agentFunctions`, `@AiAgentFunction()`), Standard Schema tool parameters, `CoreAiMcpOAuthService.createMcpTokenVerifier()` for a `@nestjs/mcp` endpoint, `RequestContext.getRequest()`, `LlmCompletionOptions.abortSignal` |
| **Bugfixes** | `HttpExceptionLogFilter` no longer throws on non-HTTP transports (the model read "Internal server error" for every refusal of an agent function) |
| **Migration Effort** | ~5 minutes: check that the app has `/auth/login` (or set `betterAuth.errorUrl`), and that no AI tool returns a secret-named field on purpose |

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@12.10.x
pnpm run update   # only if you use the starter's update script
pnpm run build
pnpm test
```

No new dependency is required. `ai`, `@nestjs/ai` and `@nestjs/resilience` are new **optional** peers — install them
only for the integrations below.

## Security: GraphQL multipart uploads (graphql-upload GHSA-5vm7-vc2x-p3w2, GHSA-qwwm-252j-9whw)

**No action needed** unless the project registers `graphqlUploadExpress()` itself (below).

`CoreModule` registers graphql-upload's `graphqlUploadExpress()` for `/graphql`, in front of every guard. Up to 12.9.x
it ran graphql-upload's own `processRequest`, which accepted any object path in the multipart `map` field:

- **GHSA-5vm7-vc2x-p3w2 (high):** a path into an upload placed by an earlier entry replaced one of its methods. A
  request with `map={"1":["variables.file"],"2":["variables.file.reject"]}` and no file fields made the parser throw
  `TypeError: upload.reject is not a function` outside any request — an uncaught exception, on which the process
  exits (`installProcessDiagnostics()` exits 1, as Node does without it). **One anonymous request took the server
  down.** A path with a `__proto__` key let a client-supplied object pass the `GraphQLUpload` scalar's check.
- **GHSA-qwwm-252j-9whw (medium):** a second file field with the name of an already resolved upload created another
  temporary file and dropped the reference to the first, which was never deleted — temporary files and file
  descriptors leaked per request.

graphql-upload fixed both in 18.0.2, which requires graphql 17; this framework runs graphql 16. 12.10.0 therefore
ships `processGraphQlUploadRequest` (`common/helpers/graphql-upload.helper.ts`): graphql-upload 17.1.0's parser with
both upstream fixes, and `CoreModule` passes it to `graphqlUploadExpress()`. Such a `map` path is answered with 400
"Invalid object path", a duplicate file field is ignored. graphql-upload stays at 17.1.0 for its scalar and middleware.

**A project that registers `graphqlUploadExpress()` itself** (its own route, its own limits) passes the framework's
parser — graphql-upload's default is the vulnerable one:

```typescript
import { processGraphQlUploadRequest } from '@lenne.tech/nest-server';
import graphqlUploadExpress from 'graphql-upload/graphqlUploadExpress.mjs';

consumer
  .apply(graphqlUploadExpress({ maxFiles: 10, maxFileSize: 10_000_000, processRequest: processGraphQlUploadRequest }))
  .forRoutes('graphql');
```

Find such registrations with `grep -rn "graphqlUploadExpress(" src/`. A project that calls graphql-upload's
`processRequest` directly switches to `processGraphQlUploadRequest` (same signature and options).

**Behaviour change:** a GraphQL variable literally named `__proto__` that receives a file is refused with 400 (input
object fields cannot use that name; names starting with `__` are reserved).

## What's New in 12.10.x

### 0. Social sign-in: provider options and the error page (Better-Auth)

- **Provider options reach Better-Auth.** Until 12.9.4 `buildSocialProviders()` handed a provider only `clientId`,
  `clientSecret` and `disableSignUp`; `tenantId`, `scope` and every other option were dropped without a word (a Microsoft
  sign-in ran against `common` with Better-Auth's default scopes). Every option on `betterAuth.socialProviders.<name>`
  except `enabled` is now passed on; the computed `clientId` / `clientSecret` / `disableSignUp` are written last, so a
  string `disableSignUp` from `NEST_SERVER_CONFIG` still cannot open a closed registration.
- **`scope` from an environment variable works.** `NSC__…__SCOPE=openid,profile,email` is split on commas or spaces.
- **`betterAuth.errorUrl`** (`string | false`, default `<appUrl>/auth/login`; a path is resolved against the app URL)
  becomes Better-Auth's `onAPIError.errorURL`. `options.onAPIError` is merged; its own `errorURL` wins.

```typescript
betterAuth: {
  errorUrl: '/auth/login',  // default; false keeps Better-Auth's page on the API host
  socialProviders: {
    microsoft: { clientId, clientSecret, tenantId: '<tenant-id>', scope: 'openid,profile,email' },
  },
},
```

A login page maps the `error` query code to its own text and never renders `error_description` — anyone can set it
through a link to `/iam/error`. Details: [Better-Auth README](../src/core/modules/better-auth/README.md), "Social
providers".

### 1. Global guards on `@nestjs/ai` and `@nestjs/mcp` calls

`@nestjs/ai` (`@AgentFunction()`) and `@nestjs/mcp` (`@Tool()`, `@Resource()`, `@Prompt()`) run every global guard,
interceptor and filter around their methods with the context types `'ai'` / `'mcp'`. The framework now resolves the
request of such a call from the call object (`caller.request`, `McpContext.request`):

- `@Roles()` on an agent function or MCP tool is decided against the request's user exactly as over HTTP, tenant
  header included.
- A **request-less** caller — `caller: { user, scopes }` (a queue job), a durable run, MCP over stdio — is
  **anonymous**: public methods run, every other one is refused with 401. To run a role-gated agent function from a job,
  authenticate there and pass a request (`caller: { request }`).
- `@Restricted` and secret-field filtering apply to the result for the request's user.

Nothing to do unless you relied on the old behaviour (which read the tool arguments).

### 2. AI SDK transport

```typescript
// A model of @nestjs/ai's AiModule.forRoot({ models }): create a connection with
// providerType 'nestjs-ai', model 'default' (the registered name), baseUrl 'nestjs-ai:default'.

// Or any AI SDK provider for database-managed connections:
await llmProviderFactory.registerAiSdkModel('anthropic', (connection, { fetch }) =>
  createAnthropic({ apiKey: connection.apiKey, fetch })(connection.model),
);
```

Requires `ai` (`>=7.0.0 <8`); `nestjs-ai` additionally `@nestjs/ai` (`>=0.0.2 <0.0.3`) and `@nestjs/resilience`
(`>=0.0.3 <0.0.4`). Outside these ranges the call / boot fails with `AiSdkPackageError` naming the range. Hand the
provider the `fetch` from the builder context, or `ai.allowedBaseUrlHosts` does not cover it.

### 3. Agent functions as AI tools

```typescript
// config.env.ts
ai: { agentFunctions: true },   // or { include: ['cancel_booking'] } / { exclude: [...] }

// on the method
@AgentFunction({ name: 'cancel_booking', description: 'Cancel a booking', inputSchema: z.object({ id: z.string() }) })
@AiAgentFunction({ destructive: true })
@Roles(RoleEnum.S_USER)
cancel({ id }: { id: string }) { ... }
```

The AI module's gates run first (role filter, policies and grants, `authorize()`, confirmation, plan mode, budgets),
then `@nestjs/ai`'s pipeline with the run's HTTP request. Roles default to the method's `@Roles()`, else `S_USER`.

### 4. Standard Schema tool parameters

```typescript
readonly parameters = z.object({ id: z.string() }) as any; // Zod 4.2+, ArkType, Valibot via toStandardJsonSchema()
```

The registry stores the JSON Schema and validates the arguments before `authorize()` and `execute()`.

### 5. A `@nestjs/mcp` endpoint with the framework's MCP OAuth server

`CoreAiMcpOAuthService.createMcpTokenVerifier({ resource })` returns a verifier for `McpModule`'s `auth.verifier`
(module README → "Your own `@nestjs/mcp` endpoint").

### 6. MCP OAuth tokens are bound to their resource (RFC 8707)

The authorization server honours `resource` at `/authorize` and `/token` (code and refresh grant) and binds it into the
code, the refresh token and the access token (`aud`). `/ai/mcp` accepts only tokens for itself, a
`createMcpTokenVerifier()` only tokens for its `resource`; an unknown `resource` is `invalid_target`. Nothing changes for
today's clients: one that names no `resource` gets a token for `/ai/mcp`, and tokens and refresh tokens issued before
12.10.0 stay valid at `/ai/mcp` (a refresh binds them to it). **SQL projects:** the tables of the MCP OAuth codes and refresh
tokens (collections `aiMcpOAuthCodes` / `aiMcpOAuthRefreshTokens` on MongoDB) gain a nullable `resource` column, which the boot adds as the owner role (`ownerUrl`);
without an owner connection add it with a migration.

### 7. Dependencies

12.10.0 declares NestJS 12.5.1. `pnpm run update` raises these pins where a nest-server-starter based project already
declares them:

| Package | From | To |
|---|---|---|
| `@nestjs/common`, `@nestjs/core`, `@nestjs/platform-express`, `@nestjs/testing` | 12.5.0 | 12.5.1 |
| `@nestjs/terminus` | 12.1.0 | 12.2.0 |
| `graphql-subscriptions` | 3.0.0 | 3.1.0 |
| `js-sha256` | 1.0.0 | 1.1.0 |
| `nodemailer` | 10.5.0 | 10.6.0 |
| `mongoose` (MongoDB projects) | 9.12.1 | 9.12.2 |

Where declared, also the optional peers `bullmq` 6.7.7, `@aws-sdk/*` 3.1171.0 and `ai` 7.0.176, and `vitest` /
`@vitest/coverage-v8` 5.1.1. `js-sha256` 1.1.0 now hashes multi-byte typed arrays (`Uint16Array`, `Float32Array`, …) by

installed, so an npm-mode project gets no new package. A vendor-mode project declares them (the core imports them
directly).

## Breaking Changes

### Failed OAuth sign-ins land on the app's login page

**Before:** a failed OAuth sign-in without an error URL of its own (state expired after ten minutes, missing or tampered;
a flow started without `errorCallbackURL`) and every `GET /iam/error` showed Better-Auth's English error page on the API
host.

**After:** they land on `<appUrl>/auth/login?error=<code>`.

**Action:** make sure the app has an `/auth/login` route that reads `error`, or set `betterAuth.errorUrl` to another
page (an absolute URL or a path). A project that customized Better-Auth's page
(`options.onAPIError.customizeDefaultErrorPage`) sets `betterAuth.errorUrl: false`. An explicit
`options.onAPIError.errorURL` still wins.

### A `scope` that is neither a string nor a list is ignored

**Before:** an object (indexed `NSC__…__SCOPE__0` variables) made every `/iam/sign-in/social` throw a `TypeError`.

**After:** it is dropped with one error at boot, and the provider asks for its default scopes — with
`disableDefaultScope: true` for none, which the provider refuses.

**Action:** write one comma-separated `NSC__…__SCOPE` variable.

### Secret fields leave AI tool results

**Before:** `CoreAiService.sanitizeResult()` ran `securityCheck()` on model instances only, and `/ai/mcp` sent
`JSON.stringify(result)`. A tool returning a lean document or a plain object handed its secret fields to the model, to
`actions[].result` and to the MCP client.

**After:** both paths use `sanitizeToolResultForModel()`: `securityCheck(user)` on every model instance at any depth —
also inside the `{ success, data }` wrapper, which `/ai/mcp` never looked into — then every field named in
`security.secretFields` or the framework defaults (also as SQL column, `password_reset_token`) is removed, at any depth.
A Mongoose document is replaced by its stripped `toJSON()`; a class instance becomes a plain copy of its own enumerable
fields (what `JSON.stringify` read anyway). An MCP OAuth user now carries `hasRole()` (string or array, as Better-Auth
users do) and `_authenticatedViaBetterAuth`, so a `securityCheck()` calling `user.hasRole()` works on that path.

**Action:** if a tool returns a field with such a name ON PURPOSE (it should not — the model and the client read it),
rename it. Over `/ai/mcp`, a result now loses what its models' `securityCheck()` hides from the caller, as it already did
in the chat. An override of `sanitizeResult()` keeps working.

## Compatibility Notes

| Pattern | Status |
|---------|--------|
| `LlmProviderFactory` subclass with its own constructor | Compatible — the new `ModuleRef` parameter is optional |
| Builder registered under `'nestjs-ai'` by the project | Compatible — `registerBuilder()` replaces the built-in one |
| Override of `OpenAiCompatibleProvider.resolveAllowedBaseUrlHosts()` / `normaliseHostEntry()` | Compatible — same contract; the default bodies now delegate to `ai-egress.helper` |
| `/ai/mcp` and the MCP OAuth server | Unchanged — still `@modelcontextprotocol/sdk` 1.x (see below) |
| Projects without `ai` / `@nestjs/ai` / `@nestjs/mcp` | Unchanged — nothing new is loaded |
| Vendor mode | The core names `ai`, `@nestjs/ai` and `@nestjs/resilience` in literal `import()` calls: the project declares them (the lt CLI adds them) |
| Vendor mode, GraphQL uploads | The core imports `busboy`, `fs-capacitor`, `http-errors` and `object-path` itself (`common/helpers/graphql-upload.helper.ts`): add them to `dependencies` at the versions in §7 — a pnpm project does not see graphql-upload's own copies |
| `graphqlUploadExpress()` registered by the project | Pass `processRequest: processGraphQlUploadRequest` (see "Security: GraphQL multipart uploads") |

**Why `/ai/mcp` stays on MCP SDK v1:** `@modelcontextprotocol/server` 2.x ships no OAuth authorization-server router
(only resource-server helpers), and `@nestjs/mcp` serves every request statelessly — no sessions, no server-initiated
elicitation for 2025 clients, which the clients in use today need for the confirmation of destructive tools. A migration
that keeps every current behaviour is a release of its own.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `AiSdkPackageError: @nestjs/ai@0.0.3 is installed, but … tested with >=0.0.2 <0.0.3` | an untested 0.x release | install a version in the range, or update `@lenne.tech/nest-server` |
| `ai.agentFunctions is set, but the application imports no AiModule.forRoot()` | the bridge needs `@nestjs/ai`'s module | import `AiModule.forRoot({ models })` or remove `ai.agentFunctions` |
| An agent function is missing from the tools | it requires `scopes` | remove `scopes`, gate it with `@Roles()` |
| A role-gated agent function answers 401 from a queue job | request-less callers are anonymous | authenticate in the job and pass `caller: { request }` |
| A `@nestjs/mcp` tool answers 401 with an MCP OAuth token | the verifier refused it (expired, `ai.mcp.roles`, unknown user) | check `ai.mcp.roles`; obtain a new token |
| A file upload answers 400 `Invalid object path for the ‘map’ multipart field …` | the `map` names a path into another upload or with a `__proto__` key | send each file at its own variable path (`variables.files.0`, `variables.files.1`) |
| Vendor mode: `Cannot find package 'busboy'` (or `fs-capacitor`, `http-errors`, `object-path`) at start | the core imports them since 12.10.0 | add them to `dependencies` (§7) |
