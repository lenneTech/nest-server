# Migration Guide: 12.4.x → 12.5.x

## 12.5.0 contains breaking changes

The version number moves only the MINOR digit (the MAJOR follows NestJS). Read §1 before you update: a project's
`GET /config` answers 404 in deployed environments from now on — once the project's controller uses the core's
`configEndpointResponse()`, which this guide asks for.

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | `GET /config` via `configEndpointResponse()` answers only in `local`, `ci` and `e2e` unless `configEndpoint` opens it, and always redacted (§1) |
| **New Features** | `redactSecrets()`, `ConfigService.getRedactedConfig()`, `configEndpointResponse()`, `isConfigEndpointEnabled()`, the `configEndpoint` setting (§1) |
| **Bugfixes** | `GET /config` of a project created before the starter redacted returned every secret of the deployment to administrators (§1). The `ConfigService` debug output (`warn: true`) printed the configuration unredacted (§2). `ConfigService#mergeProperty(key, value)` merged nothing (§3) |
| **Migration Effort** | One line in the project's `ServerController` (§1). Nothing else |

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@12.5.0
pnpm run update   # nest-server-starter based projects: aligns the pins the framework raised
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual, then apply §1 to `src/server/server.controller.ts`.

## 1. `GET /config`: redacted by the core, closed in deployed environments

The route lives in project code — the starter's `ServerController`. Until the starter redacted it (October 2026) it
returned `configFastButReadOnly` as it is: the database URI with its password, the JWT and Better-Auth secrets, the
mail password, API keys. Every project created before that still does, and an administrator account — or a stolen
administrator session — was enough to read them.

**What the core now provides:**

- `redactSecrets(value, extraSecretKeys?)` — the framework's one masker (moved from the Hub, where it stays available
  as `maskConfigDeep`). It masks by key name (secret, password, pass, token, key, credential, encryption, dsn, salt, …),
  masks the password of a connection URI and every secret-named query parameter of a URI, works through nested values,
  and masks EVERYTHING below a secret-named key except booleans.
- `ConfigService.getRedactedConfig()` — the running configuration through `redactSecrets()`, with the framework's
  secret fields and your `security.secretFields`. The Hub config panel shows the same view.
- `configEndpointResponse()` — the body of `GET /config`: the redacted configuration, or a 404 where the endpoint is
  closed.
- `configEndpoint` — whether it answers:

| `configEndpoint` | `local` / `ci` / `e2e` | every other environment (`develop`, `test`, `production`, …) |
|---|---|---|
| not set | answers | **404** |
| `true` | answers | answers |
| `false` | 404 | 404 |

A value that is not a boolean counts as not set. Environment variable: `NSC__CONFIG_ENDPOINT=true`.

**What to do** — in `src/server/server.controller.ts`, replace the body of the `config()` handler:

```typescript
// Before (verbatim configuration, or the starter's own redact-secrets.util.ts)
@Get('config')
@Roles(RoleEnum.ADMIN)
config() {
  return JSON.parse(JSON.stringify(this.configService.configFastButReadOnly));
}

// After
import { configEndpointResponse } from '@lenne.tech/nest-server';

@Get('config')
@Roles(RoleEnum.ADMIN)
config() {
  return configEndpointResponse();
}
```

A starter-based project that already redacts with `src/server/common/utils/redact-secrets.util.ts` can delete that
file: the core's masker covers everything it did, and also what it let through (values nested below a secret-named
key, a password passed as a URI query parameter).

**Who calls `/config`?** No frontend or script of the lenne.Tech stack does; it is an administrator's debugging aid.
**If your project's own admin UI or tooling reads `/config` on a deployed stage, switch it back on there explicitly:**

```bash
NSC__CONFIG_ENDPOINT=true    # or configEndpoint: true in config.env.ts for that environment
```

The endpoint then answers in that environment again, and the answer stays redacted: secret values read `***`, every
other setting is unchanged. An admin UI that displayed secrets from `/config` gets `***` for them from now on — that is
the point of this change.

**The status codes:** without a session the route's `@Roles(ADMIN)` still answers 401; an administrator gets 404
where the endpoint is closed, so it reads like a route that does not exist.

## 2. The `ConfigService` debug output is redacted

`new ConfigService(config, { warn: true })`, `mergeConfig(…, { warn: true })` and `setConfig(…, { warn: true })` print
the merged configuration — an opt-in debugging aid since 12.0.0. That output now goes through the same redaction, so
a debug session no longer writes the deployment's secrets to a log.

## 3. `ConfigService#mergeProperty(key, value)` merges the value

The instance method forwarded its `options` in place of `value` to the static one, so it merged `undefined`. It now
merges the value as its signature says. `ConfigService.mergeProperty()` (static) was not affected.

## Compatibility Notes

| Pattern | Status |
|---|---|
| A `ServerController` returning `configFastButReadOnly` | Still unredacted until you apply §1 — the core cannot reach a route in project code |
| `configEndpointResponse()` in `local` / `ci` / `e2e` | Answers as before, redacted |
| E2E suites reading `/config` (`NODE_ENV=e2e`) | Unchanged, apart from masked secret values |
| `maskConfigDeep` (Hub) | Still exported, now the same function as `redactSecrets` — values below a secret-named key keep their structure (masked) and booleans stay visible |
| Health check, `/meta`, error responses | Unchanged — they carry no configuration |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `GET /config` answers 404 for an administrator | Deployed environment without `configEndpoint` | `NSC__CONFIG_ENDPOINT=true` on that stage, if you need it |
| A value you need reads `***` | Its key matches a secret pattern | Read it from the environment of the deployment; `/config` never shows secrets |
| A secret under an unusual key appears in plain text | No pattern matches it | Add the key to `security.secretFields` |
