## Overview

| Category             | Details                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| **Bugfixes**         | No framework code changes; security release of the runtime dependency `undici` (§3)                     |
| **New Features**     | None                                                                                                     |
| **Framework API**    | Unchanged — no new exports, no changed signatures                                                        |
| **Dependencies**     | `mongoose` 9.10.4 → 9.11.2 and `mongodb` 7.6.0 → 7.7.0 (both `dependencies`, raised together, §1); **`undici` 7.30.0 → 7.30.1 (security release, §3)**; `nodemailer` 10.1.0 → 10.1.2; `@getbrevo/brevo` 6.0.3 → 6.2.0; overrides `@graphql-tools/utils` → 12.0.4, `undici` → 7.30.1, `qs` → 6.16.1 |

Typed `lean()` / `bulkWrite()` code may need a type adjustment (§2) |

## Quick Migration

```bash
pnpm run update            # starter-based projects: raises every pin the framework raised
pnpm why mongodb           # must show ONE version: 7.7.0
```

If `pnpm why mongodb` lists 7.6.0 next to 7.7.0, raise the project's own `mongodb` entry to `7.7.0` (§1). If your
project has its own `undici` override, raise it to 7.30.1 (§3) — `pnpm audit` does not flag this one yet.

Vendor-mode projects pick up the core with `/lt-dev:backend:update-nest-server-core`; raise `mongoose` and `mongodb`
in the project's `package.json` to the versions above in the same step.

## 1. mongoose 9.11 and mongodb 7.7 move together

mongoose 9.11.x requires `mongodb ~7.7`, so both are raised in this release. nest-server declares `mongodb` under
`dependencies`. nest-server-starter keeps it under `devDependencies` — and that pin is **not test-only**: Better-Auth's
MongoDB adapter (`@better-auth/mongo-adapter`, used by nest-server's IAM module) resolves its `mongodb` peer from the
project's own `mongodb` entry, in the production image too.

Until this release, `pnpm run update` (the starter's `extras/sync-packages.mjs`) raised a pin only when the framework
declared it **in the same section**. A project with `mongodb` in `devDependencies` therefore stayed on 7.6.0 while the
framework's mongoose brought 7.7.0: two driver copies. Where the project's lockfile still holds the older `bson` for
the old driver (any lockfile not refreshed since bson 7.3), there are two `bson` copies as well. The adapter checks ids
with `instanceof ObjectId` against ITS driver's bson, the ids come from the framework's — so the check fails, the
adapter throws `MongoAdapterError: Invalid id value`, and authenticated requests answer **401**. With a single shared
bson it stays a typing problem in tests (`Db` / `MongoClient` from the test helpers no longer match the project's own
import). Neither is acceptable, and which one a project gets depends on its lockfile history, so raise the pin.

The starter's update script now raises a package the framework **ships** (`dependencies`) in whichever section the
project keeps it. A package the framework only develops and tests with (`devDependencies`) still raises only the
project's own `devDependencies` — never a runtime pin. That keeps the better-auth trio where it belongs: the framework
holds it as devDependencies (its test versions, with a peer range as the contract), the project holds it as
dependencies and owns that version, because its api and app must resolve the same better-auth. The rule lives in
`extras/align-package-versions.mjs`, and nest-server's consumer gate (`pnpm run check:consumer`) applies the identical
rule before every release.

**What to do:**

- **Your project still has the old `extras/sync-packages.mjs`:** raise `mongodb` to `7.7.0` by hand (also
  `json-to-graphql-query`, if you keep it in `devDependencies` and it lags), or copy `extras/sync-packages.mjs` and
  `extras/align-package-versions.mjs` from nest-server-starter. **This step is required** — skipping it breaks sign-in.
- **Your project has `mongodb` in `dependencies`:** `pnpm run update` already raised it; nothing to do.
- **Check either way:** `pnpm why mongodb` must list exactly one version.

## 2. mongoose 9.11 type changes

No runtime behaviour your code relies on changed, but two typing changes can surface in a project's own code:

- `lean()` now passes its result type into the query, so a `lean<T>()` result is narrowed to `T`. Code that assigned
  the result to an incompatible type now gets a compile error instead of a silent mismatch.
- `UpdateOneModel` / `UpdateManyModel` (`bulkWrite()` operations) are typed like `UpdateQuery`. An update document that
  was accepted by the looser type may now need its operators spelled out (`$set`, `$push`, …).

Runtime fixes that come along (no action needed): validators on document arrays under nested paths no longer run
twice, `bulkWrite()` casts array filter values, cursors await driver cleanup on destroy. The mongodb 7.7 driver
recovers from a failed OIDC token fetch instead of failing every later operation on that client.

## 3. undici 7.30.1 is a security release

undici 7.30.1 fixes four high and four medium advisories (GHSA-qrxm-fqhp-jwvm, GHSA-2m5v-pch6-74hx,
GHSA-4w7w-5xrc-9h26, GHSA-xjj6-f33q-929c high; GHSA-55wc-3pg8-jfw6, GHSA-f72v-6w45-q472, GHSA-4qv8-2p9j-2685,
GHSA-9fm3-97px-rjf6 medium). They were published as repository advisories, so **`pnpm audit` does not report them
yet** — a green audit says nothing about this release. nest-server uses undici at runtime for `outboundFetch()` (the
SSRF-guarded fetch for user-entered URLs), and one of the fixes concerns function-valued Agent options, which that
helper's guarded connector is.

**What to do:**

- **Nothing for nest-server's own dependency** — `pnpm run update` raises it.
- **Your project carries its own `undici` override** (starter-derived projects do, for the
  `@compodoc/compodoc > cheerio > undici` path): raise key and target together, e.g.
  `'undici@>=7.0.0 <7.30.0': 7.30.0` → `'undici@>=7.0.0 <7.30.1': 7.30.1`. The old entry would otherwise keep that path
  on the vulnerable 7.30.0, because cheerio's `^7.19.0` intersects the old key.
- **Check:** `pnpm why undici` lists only 7.30.1.

Also raised in the same way (no advisory, removes a hold-back): `qs` override `<6.16.0` → `<6.16.1` (6.16.1), and
`nodemailer` 10.1.2, which strips credentials on a cross-origin redirect.

## Compatibility Notes

| Pattern | Status |
| ------- | ------ |
| `mongodb` in `dependencies` of the project | Raised by `pnpm run update` as before |
| `mongodb` in `devDependencies` of the project (starter default) | Raised only by the new update script — otherwise raise by hand, **required** (§1) |
| better-auth / `@better-auth/*` in the project's `dependencies` | Never raised from the framework's devDependencies — the project owns that version, as before |
| `lean<T>()` with an explicit result type | May need a type adjustment (§2) |
| `bulkWrite()` with typed `updateOne` / `updateMany` operations | May need operators spelled out (§2) |
| Routes with `@Roles()` + `@UseGuards(AuthGuard(BETTER_AUTH))` | Unchanged. nest-server-starter dropped these redundant guards from its `UserController`; removing them in your project is optional |

## Troubleshooting

**Sign-in or every authenticated request answers 401, the log shows `MongoAdapterError: Invalid id value`**
Two mongodb (and bson) versions are installed, and Better-Auth's MongoDB adapter uses the project's older one.
`pnpm why mongodb` shows both; raise the project's own `mongodb` entry to 7.7.0, run `pnpm install`, and rebuild the
image (§1).

**Type errors around `Db`, `MongoClient` or `Collection` in tests after the update**
Same cause, same fix: two mongodb versions are installed. Raise the project's own entry to 7.7.0 and run
`pnpm install`.
