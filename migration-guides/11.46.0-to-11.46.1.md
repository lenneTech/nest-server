# Migration Guide: 11.46.0 → 11.46.1

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | None |
| **New Features** | None |
| **Bugfixes** | Security: mongodb 7.8.0 closes GHSA-77w5-j825-v4qm (`timeoutMS`) and a flaw in the host-name check of SRV lookups (`mongodb+srv://`) (§1). Error responses of `HttpExceptionLogFilter` no longer contain `options` / `cause` (§2) |
| **Migration Effort** | Update. A project that pins mongoose / mongodb itself — vendored cores included — raises them (§1) |

11.46.1 is a security patch for 11.46.0 (`latest-11`). Besides the dependency update, one framework fix: error
responses no longer carry `options` / `cause` (§2). Both changes also ship in 12.8.5 (`latest`; the mongoose / mongodb update already in 12.8.4) and 12.6.8
(`latest-12.6`).

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@11.46.1
pnpm run update   # nest-server-starter based projects
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual, and raise mongoose / mongodb in the project's own
`package.json` (§1).

## 1. mongoose 9.12.0 and mongodb 7.8.0 (security)

On 11.x mongoose and mongodb are regular dependencies of the framework, so an npm-mode project gets both with the
update. mongoose 9.12.0 moves to the mongodb driver 7.8.0, which closes two flaws present in every earlier 7.x:

- **GHSA-77w5-j825-v4qm / CVE-2026-119179** (high): with `timeoutMS`, a connection-pool desynchronization after an
  operation timeout could hand one user's data to another. Only projects that set `timeoutMS` themselves are affected —
  the framework never sets it. Since 7.8.0 `timeoutMS` is a no-op; use `serverSelectionTimeoutMS`, `socketTimeoutMS`,
  `waitQueueTimeoutMS` and `maxTimeMS` instead.
- **SRV host-name verification** (mongodb `>= 3.3.3 < 7.8.0`, no GHSA): a host returned by the SRV lookup of a
  `mongodb+srv://` URL was not verified properly, so whoever controlled the DNS answer could redirect the driver to a
  host outside your domain. Projects with `mongodb://host1,host2` URLs are not affected.

Neither appears in `pnpm audit`, so the update is the only signal.

**What to do:** nothing for an npm-mode project that does not pin mongoose itself. A project that pins mongoose or
mongodb itself — every vendor-mode project does — sets them to `9.12.0` / `7.8.0`; mongoose 9.11 pins the driver to
`~7.7`, so raising mongodb alone leaves mongoose's own copy vulnerable:

```bash
pnpm add mongoose@9.12.0 mongodb@7.8.0
```

## 2. Error responses no longer contain `options` / `cause`

`HttpExceptionLogFilter` (registered by nest-server-starter's `main.ts` while `logExceptions` is on, its default)
answered a REST request with every field of the exception — including `options` and the `cause` the throwing code
passed (`new BadRequestException('…', { cause: dbError })`). An internal error message, a query or a connection
string could reach the client that way. Error responses now leave `options` and `cause` out; `response`, `status`,
`message` and `name` stay as before, so frontends reading them need no change. The cause is still logged.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Two mongodb copies in `pnpm why mongodb` | The project pins mongoose 9.11 or mongodb 7.7 | `pnpm add mongoose@9.12.0 mongodb@7.8.0` |
| Operations no longer time out after `timeoutMS` | `timeoutMS` is a no-op since mongodb 7.8.0 | `serverSelectionTimeoutMS`, `socketTimeoutMS`, `maxTimeMS` |
