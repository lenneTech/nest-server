# Migration Guide: 11.42.9 → 11.42.10

## Overview

| Category             | Details                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| **Requirement**      | `engines.node` is now `>= 22.15` (was `>= 22.12`). In practice the floor already applied — see §1        |
| **Security**         | Recommended `@graphql-tools/utils` override target moves from 12.0.1 to 12.0.3 (§2)                       |
| **Dependencies**     | `nodemailer` 10.0.16 (bug fixes only). Dev tooling: transitive `handlebars` 4.7.10 (§3)                   |
| **Breaking Changes** | None in the API                                                                                           |
| **Migration Effort** | None for projects on Node ≥ 22.15. Projects that carry their own `@graphql-tools/utils` override should raise it (§2) |

## Quick Migration

```bash
pnpm update @lenne.tech/nest-server
```

Vendor-mode projects pick it up with the core update. No code or configuration change is required.

## 1. Node ≥ 22.15

The declared minimum Node version rises from 22.12 to 22.15. This changes the declaration, not the reality:
`@apollo/server` resolves `@graphql-tools/schema` 10.1.3, which requests `@graphql-tools/utils ^12.0.3`, and
that in turn requires `@whatwg-node/promise-helpers` 2 — whose own `engines` field demands Node `>=22.15.0`.
Every fresh install of a GraphQL-enabled project has carried that requirement since those releases came out.
The framework's `engines` field now says so instead of promising a floor its own dependency tree does not
honour.

Check the Node version wherever the server runs:

```bash
node --version   # must print v22.15.0 or newer (any Node 24 qualifies)
```

The places to look: the Docker base image (`FROM node:…`), the CI runner's Node version, and the version a
host or PaaS pins. The starter's Dockerfile and the framework's own CI already run Node 24.

## 2. `@graphql-tools/utils` override: target 12.0.3

Overrides in this package's `pnpm-workspace.yaml` do not reach your project (see
[security-overrides.md](../docs/security-overrides.md)), so a project that copied the
`@graphql-tools/utils` entry for GHSA-7mx3-vvmw-hjmv holds its own. Until now the recommended target was
12.0.1, because 12.0.2+ needs Node ≥ 22.15. With the framework's floor at 22.15, take the newest 12.x:

```yaml
# Before
overrides:
  '@graphql-tools/utils@>=12.0.0 <12.0.1': '12.0.1'

# After
overrides:
  '@graphql-tools/utils@>=12.0.0 <12.0.3': '12.0.3'
```

```bash
pnpm install
pnpm update --depth Infinity @graphql-tools/schema @graphql-tools/merge
```

Why it matters beyond tidiness: the key intersects the `^12.0.0` range that `@graphql-tools/schema` and
`@graphql-tools/merge` request, so a target behind the newest 12.x holds them back too. Commit
`pnpm-workspace.yaml` and `pnpm-lock.yaml` together — a workspace file without the re-installed lockfile fails
every `pnpm install --frozen-lockfile`, typically in the Docker build.

Afterwards `@nestjs/graphql` 13.4.5 still brings its own exact-pinned `@graphql-tools/schema` 10.1.0 /
`merge` 9.2.3 next to the 10.1.3 / 9.2.6 that `@apollo/server` uses. That is expected: both copies share the
single overridden `@graphql-tools/utils` 12.0.3 and the single `graphql`.

Projects still on Node < 22.15 keep the 12.0.1 target until they upgrade Node.

## 3. Dependency updates

- **`nodemailer` 10.0.15 → 10.0.16** — bug fixes in the address parser and cookie handling, no API change.
  A project that carries a lock-step `nodemailer` override (nest-server-starter does) should raise it to
  `'nodemailer@<10.0.16': '10.0.16'`.
- **`handlebars` 4.7.10 (dev tooling only)** — three advisories (GHSA-8r5x-fm3f-whwj, GHSA-p8wg-vrv2-v86f,
  GHSA-xw65-4hp5-5hc7) reach projects through `@compodoc/compodoc`, which already allows the fixed version.
  If `pnpm audit` reports them in your project, refresh the stale lockfile entry instead of adding an override:

  ```bash
  pnpm update --depth Infinity handlebars
  ```

## Compatibility Notes

| Pattern | Status |
| ------- | ------ |
| Projects on Node 24 (starter Dockerfile, CI) | Unaffected |
| Projects on Node 22.12 – 22.14 | Already outside what `@graphql-tools/utils` 12.0.3 declares; upgrade Node |
| Vendor-mode projects | The core carries no `engines` field — check the Node version of your own runtime (§1) |
| `engine-strict=true` in `.npmrc` | Installs now fail on Node < 22.15 instead of warning |

## Troubleshooting

| Symptom | Cause | Fix |
| ------- | ----- | --- |
| `pnpm install` warns `Unsupported engine` for `@whatwg-node/promise-helpers` | Node older than 22.15 | Upgrade Node (§1) |
| `ERR_PNPM_UNSUPPORTED_ENGINE` for `@lenne.tech/nest-server` | `engine-strict` with Node < 22.15 | Upgrade Node (§1) |
| `pnpm audit` reports `@graphql-tools/utils` after updating | Your own override still targets an older version, or an old `@graphql-tools/schema` 10.0.x pulls utils 11.x | Raise the override and refresh schema / merge (§2) |
| `pnpm audit` reports `handlebars` via `@compodoc/compodoc` | Stale lockfile entry | `pnpm update --depth Infinity handlebars` (§3) |
