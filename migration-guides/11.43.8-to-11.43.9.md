## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@11.43.9

pnpm run build

```

latest tag, which is on a newer line).

## 1. `revoke-session` by id for users the legacy migration linked

**Why:** since 11.43.8, `POST /iam/revoke-session` accepts `{ sessionId }` and looks the session up among the caller's own
sessions. It looked the caller up under `user.id`. The session lookup prefers a **stored** `id` field over `_id`. When
the legacy migration links a user (on its first IAM sign-in, for example a user created through `POST /users` or the
legacy sign-up), it writes an `id` of its own next to `_id`. Every session references `_id`. So for such a user no
session was found, nothing was revoked, and the request still answered `{ status: true }`. The error went toward the
safe side: never another user's session.

**What changed:** the caller is looked up under the `userId` of its own session. The ownership check is unchanged.

**Your project:** nothing to do. A project that copied `resolveRevokeSessionId()` into its own core takes the session's
`userId` first (`req.betterAuthSession.session.userId`).
