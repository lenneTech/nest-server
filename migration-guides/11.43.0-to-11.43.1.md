## 1. Bearer JWTs answered 401 when only the server `baseUrl` was set

Better-Auth signs every JWT with `iss` and `aud` set to the base URL it runs on. `createBetterAuthInstance()`
resolves that base URL as `betterAuth.baseUrl` → the server's `baseUrl` → the localhost default, and Better-Auth
stores the **origin** of the result. The framework verified Bearer JWTs against
`CoreBetterAuthService.getBaseUrl()`, which read only `betterAuth.baseUrl` and otherwise answered
`http://localhost:3000`.

So as soon as a deployment set the server's `baseUrl` without also setting `betterAuth.baseUrl`, the two disagreed,
and every Bearer JWT was refused with `401 #LTNS_0100` (`unexpected "iss" claim value` in the debug log). That is the
configuration `nest-server-starter` ships (`baseUrl: process.env.BASE_URL`), every stage that sets `NSC__BASE_URL`,
and every `lt dev up`. Cookie sessions were unaffected, so the defect surfaced only for clients in JWT mode — for
example `@lenne.tech/nuxt-extensions` once it switches to JWT after the login, which then received 401 on every
request.

`getBaseUrl()` now reads the base URL off the live Better-Auth instance and returns its origin — exactly the value
Better-Auth signs with. A trailing slash, a path or a default port in the configured value
(`https://api.example.com/`, `https://example.com/api`, `https://api.example.com:443`) is not part of the claim and
no longer causes a mismatch either.

**What to check:**

- **You set `betterAuth.baseUrl` (or `NSC__BETTER_AUTH__BASE_URL`) only to work around this:** it can go. It still
  wins over the server's `baseUrl` when set, so leaving it in place changes nothing.
- **Your own code calls `getBaseUrl()`:** it now returns the URL Better-Auth actually runs on, as an origin. Code
  that joined an absolute path onto it (`new URL('/iam/sign-in/email', getBaseUrl())`) keeps working; code that
  relied on a path being part of the returned value must append that path itself. With only the server's `baseUrl`
  set, it now answers that URL instead of `http://localhost:3000`.
- **A vendor-mode project patched `getBaseUrl()` locally** for the same reason: the patch becomes obsolete with this
  core update and can be dropped.

## Compatibility Notes

| Pattern | Status |
| ------- | ------ |
| Only `baseUrl` / `NSC__BASE_URL` set (starter default, `lt dev up`) | Bearer JWTs accepted again |
| `betterAuth.baseUrl` set explicitly | Unchanged |
| Neither set (`local` / `ci` / `e2e` defaults) | Unchanged — both sides use `http://localhost:3000` |
| Cookie-only clients | Unchanged |
| A JWT naming another issuer | Still refused |

## Troubleshooting

**Bearer requests still answer 401 after the update**
Decode the token (`iss` claim) and compare it with `getBaseUrl()`. They must be identical. If they differ, check
whether `betterAuth.options.baseURL` overrides the base URL with something that is not an absolute URL — then the
framework falls back to the configured value.
