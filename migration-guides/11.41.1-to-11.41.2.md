# Migration Guide: 11.41.1 → 11.41.2

## Overview

| Category | Effort | Applies to |
|----------|--------|-----------|
| **Security** | none | `nodemailer` 9.0.5 → 9.1.1 (four advisories, one high) arrives through this package's `dependencies` |
| **Security** | one override, ~2 min | `multer` 2.2.0 → 2.3.0 (three high, one low): **your project has to add an override** — see below |
| Tooling | none | Framework repo only: `oxlint --fix-suggestions` removed, `.gitattributes`, non-blocking Windows CI |

No API change and no configuration change. The multer fix does enforce file size limits that crafted uploads could previously bypass.

## Quick Migration

```bash
pnpm update @lenne.tech/nest-server
```

```bash
# Is a vulnerable multer still in your tree? Anything below 2.3.0 means: add the override below.
pnpm why multer
pnpm audit
```

## Security: multer needs an override in your project

`@lenne.tech/nest-server` now declares `multer: 2.3.0`, but that does not reach the copy that
uploads actually go through. `@nestjs/platform-express` declares `"multer": "2.2.0"` as an **exact
pin** in every 11.2.x, so your tree ends up with both versions, and `FileInterceptor` uses 2.2.0.
The advisories ([GHSA-wc9g-mqfw-jrwm](https://github.com/advisories/GHSA-wc9g-mqfw-jrwm),
[GHSA-535w-7cp7-47q4](https://github.com/advisories/GHSA-535w-7cp7-47q4),
[GHSA-qfvm-cv95-jqjf](https://github.com/advisories/GHSA-qfvm-cv95-jqjf) — DoS via crafted multipart
input; [GHSA-qvfw-j98x-7q72](https://github.com/advisories/GHSA-qvfw-j98x-7q72) — file size limit
bypass) are in that copy.

Overrides declared in this package do not travel with it (see
[docs/security-overrides.md](../docs/security-overrides.md)). Add the entry to your project's
`pnpm-workspace.yaml` (pnpm 11+; `pnpm.overrides` in `package.json` on pnpm 10 and earlier):

```yaml
overrides:
  # @nestjs/platform-express exact-pins multer@2.2.0 (GHSA-wc9g-mqfw-jrwm and three more, patched >=2.3.0).
  # Keep the target in LOCKSTEP with the multer version @lenne.tech/nest-server declares.
  # Remove once @nestjs/platform-express requests >=2.3.0 itself.
  'multer@>=2.0.0 <2.3.0': '2.3.0'
```

If your project declares `multer` directly, raise it to `2.3.0` as well, so the tree carries exactly
one copy.

```bash
pnpm install
pnpm why multer   # expect a single multer@2.3.0
```

Projects created from nest-server-starter after 2026-09-15 already carry both.

Vendor-mode projects adopt the `multer` and `nodemailer` bumps through the core update instead of
`pnpm update`. The override is needed there all the same, because `@nestjs/platform-express` is
installed from npm in both modes.

## Under the hood

Changes to the framework repository that do not reach consumers:

- `oxlint --fix-suggestions` is gone from `lint:fix`, the pre-commit `lint-staged` config and
  `scripts/check.mjs`. oxlint's `no-console` suggestion deletes the whole call, so a commit or a
  `pnpm run check:fix` silently removed `console.log` statements from `src/` and `tests/`.
- The `hono` and `js-yaml` 4.x overrides were raised to 4.13.7 and 4.3.2. Both are inert: their
  consumers reach the fixed versions on their own ranges. Nothing to mirror.
- `.gitattributes` pins LF line endings, so a Windows checkout no longer turns
  `docker-entrypoint.sh`, the `Dockerfile` and `bin/migrate.js` into CRLF.
- `extras/sync-version.ts` stages the lockfile with `execFileSync`, so a repository path containing
  a space works.
- A non-blocking Windows CI job (`windows.yml`) runs install, build and unit tests.
