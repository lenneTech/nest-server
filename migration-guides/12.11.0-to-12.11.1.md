# Migration Guide: 12.11.0 → 12.11.1

## Overview

| Category | Details |
|---|---|
| **Breaking Changes** | None |
| **New Features** | None |
| **Bugfixes** | Turning two-factor authentication off no longer signs out a client that holds a JWT alone (`cookies: false`): the answer of `POST /iam/two-factor/disable` carries the JWT of the new session (§1) |
| **Security** | MongoDB driver 7.9.1 (three medium advisories, §2) |
| **Migration Effort** | Package update (`pnpm run update` raises the MongoDB driver pins). JWT clients store the `token` of the disable answer, as they do after `verify-totp` |

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@12.11.1
pnpm run update   # nest-server-starter based projects
pnpm run build
pnpm test
```

**Vendor mode**: run `/lt-dev:backend:update-nest-server-core` as usual.

## 1. Bugfix: two-factor disable answers with the JWT of the new session

**No backend action needed.** A JWT client takes the new `token` from the answer.

Since 12.11.0 a Better-Auth JWT is bound to the session it was issued from (see the 12.10.x → 12.11.x guide, §1).
Better-Auth replaces the session on these routes: it creates a new one, sets its cookie and deletes the request's
session.

| Route | Answer in 12.11.0 | Answer since 12.11.1, where the body carries a token |
|---|---|---|
| `POST /iam/two-factor/disable` | `{ status: true }` | `{ status: true, token }` |
| `POST /iam/two-factor/enable` with `method: 'otp'` | `{ method: 'otp' }` | `{ method: 'otp', token }` |
| `POST /iam/two-factor/enable` with `skipVerificationOnEnable` | `{ method: 'totp', totpURI, backupCodes }` | the same plus `token` |
| `POST /iam/two-factor/verify-totp` (first confirmation while enabling) | `{ token, user }` with the JWT of the new session | unchanged |

`token` is the JWT of the new session. The body carries a token when cookies are disabled (`cookies: false`) or
`cookies.exposeTokenInBody` is on; in the default cookie mode the answer stays as it is, and the session cookie carries
the new session.

In 12.11.0 a client without a session cookie kept a JWT of the deleted session after turning 2FA off: every request
answered `401`, and it could not fetch a new JWT from `GET /iam/token` either. The user had to sign in again. The
framework's default configuration reaches only the disable route; the two enable variants need a project's own
`twoFactor` setup (`otpOptions.sendOTP`, `skipVerificationOnEnable`).

**Clients:** store the `token` of these answers when it is present, the same way as after `verify-totp`.
`@lenne.tech/nuxt-extensions` 4.0.5 and `@lenne.tech/ng-base` 22.1.3 do this. Against 12.11.0 the field is absent and
nothing changes.

## 2. Dependencies: MongoDB driver security fix

| Package | 12.11.0 | 12.11.1 | Why |
|---|---|---|---|
| `mongodb` (optional peer) | 7.8.0 | 7.9.1 | GHSA-779g-w5r4-wr2x (credentials from the connection string in parse errors and in logged clients), GHSA-prmg-mvj2-c4f7 (NUL bytes in SASL PLAIN credentials change the authenticated identity), GHSA-c5cf-gf4q-92vj (OIDC bearer token leak); all medium, fixed in 7.9.x only |
| `mongoose` (optional peer) | 9.12.3 | 9.13.0 | the first mongoose that allows `mongodb ~7.9` |
| `ioredis` (optional peer) | 6.0.0 | 6.1.0 | maintenance |

These packages are optional peers: the project pins them. In a nest-server-starter based project, `pnpm run update`
raises its `mongoose` and `mongodb` pins (and `ioredis`, where declared) to these versions. Raise `mongoose` and `mongodb`
together; mongoose 9.12.3 accepts only `mongodb ~7.8`, and two driver copies give two `bson` copies, which breaks
Better-Auth's MongoDB adapter (`instanceof ObjectId`). The peer ranges stay as they are (`mongodb >=7.8.0 <8`,
`mongoose >=9.12.0 <10`).

## Compatibility Notes

| Pattern | Status |
|---|---|
| Cookie mode (`cookies: true`, the default) | Unchanged |
| JWT mode (`cookies: false`) with a frontend library that takes the token | Stays signed in after turning 2FA off |
| A project's own controller that forwards to Better-Auth through `sendBetterAuthResponse(res, response)` | Works as before; pass `{ requestSessionToken }` as the third argument to get the new rule on its routes |
| An override of `CoreBetterAuthService.presentSessionTokens(response)` | Still called; the second argument `{ requestSessionToken }` is new and optional |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Signed out right after turning 2FA off in JWT mode | The client keeps the JWT of the replaced session | Update to 12.11.1 and store the `token` of the disable answer |
| `401` right after enabling 2FA in JWT mode | The first `verify-totp` replaced the session (12.10.x → 12.11.x guide, §1) | Use the `token` of the `verify-totp` answer |
