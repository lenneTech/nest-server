# Migration Guide: 12.3.1 → 12.3.2

## Overview

| Category             | Details                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------- |
| **New Features**     | Optional Reply-To for outgoing mail: `email.defaultReplyTo` and a per-call `replyTo` (§1)               |
| **Breaking Changes** | None                                                                                                    |
| **Migration Effort** | None. Set `email.defaultReplyTo` only if answers to your mail should go to another address (§1)         |

## Quick Migration

```bash
pnpm add @lenne.tech/nest-server@12.3.2
pnpm run update   # nest-server-starter based projects
```

Vendor-mode projects pick it up with the core update (`/lt-dev:backend:update-nest-server-core`).

## 1. Reply-To for outgoing mail

`EmailService.sendMail()` can set a `Reply-To` header, so a recipient's answer goes to another address than the
sender, e.g. a shared support mailbox while mail goes out from `noreply@…`. Nothing changes until you set it.

```typescript
// config.env.ts
email: {
  defaultSender: { email: 'noreply@example.com', name: 'Example' },
  defaultReplyTo: 'support@example.com', // or '"Example Support" <support@example.com>'
},
```

As an environment variable:

```bash
NSC__EMAIL__DEFAULT_REPLY_TO=support@example.com
```

A call can override it, or send one mail without it:

```typescript
await this.emailService.sendMail(to, subject, { replyTo: 'sales@example.com', htmlTemplate, templateData });
await this.emailService.sendMail(to, subject, { replyTo: false, htmlTemplate, templateData });
```

The default applies to every mail the service sends over SMTP, Better-Auth's verification and password-reset mail
included. Mail sent through Brevo (`brevo.apiKey`) or Mailjet is not affected: their templates carry their own
reply-to. A value that is not a string is ignored with one warning rather than stopping the mail.
